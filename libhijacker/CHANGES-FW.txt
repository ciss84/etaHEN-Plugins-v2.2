- Table KERNEL_ADDRESS_ALLPROC / SECURITY_FLAGS / ROOTVNODE fournie par
  l'utilisateur confirme que le firmware 11.40 (0x11400000) partage les
  MEMES offsets noyau que 11.00/11.20/11.60 :
    allproc        = DATA_BASE + 0x2875D70
    security_flags = DATA_BASE + 0xD8C064
    root_vnode     = DATA_BASE + 0x30B7510
- offsets.cpp : V1140 ajoute dans les 5 switch (allproc, security_flags,
  qa_flags, utoken_flags, root_vnode), groupe avec V1100/V1120/V1160.
  Teste sur l'hote (switch isole, build g++), toutes les versions
  11.00/11.20/11.40/11.60/12.xx/13.xx renvoient les bonnes valeurs, et un
  firmware inconnu tombe toujours proprement dans le default (-1).
- libSelfDecryptor/selfpager.c (pagertab) : PAS touche pour 11.40. La table
  pagertab separe deja 11.00/11.20 (0xDF1940) de 11.60 (0xDF1960), donc le
  regroupement "11.00/11.20/11.40/11.60 identiques" valable pour offsets.cpp
  ne s'applique pas forcement au pagertab. Reste en ENOSYS tant qu'aucune
  valeur verifiee n'est trouvee.

Ajout de 4 nouvelles fonctions dans offsets.cpp (pas d'equivalent avant) :
- text_base_delta()   : KERNEL_ADDRESS_TEXT_BASE - DATA_BASE (SIGNE, negatif)
- bus_data_devices()  : KERNEL_ADDRESS_BUS_DATA_DEVICES - DATA_BASE
- vmspace_p_root()    : KERNEL_OFFSET_VMSPACE_P_ROOT (offset de struct, pas lie a DATA_BASE)
- vmspace_vm_pmap()   : KERNEL_OFFSET_VMSPACE_VM_PMAP (idem)
Couverture : 1.00 -> 14.10 (table fournie par l'utilisateur).
IMPORTANT : aucun appelant existant dans le code actuel (hijacker.cpp, dbg.cpp,
elf.cpp, etc.) n'utilise ces 4 fonctions. Elles sont ajoutees pretes a
l'emploi mais dormantes -- NON VERIFIEES sur console, et pas branchees a une
fonctionnalite pour l'instant.
Teste sur l'hote (g++, switch isole) : valeurs correctes pour 1.00, 1.05,
2.00, 6.00, 11.00, 11.40, 13.60, 14.00, 14.10 ; un firmware inconnu
retombe proprement sur le garde-fou (-1 / 0 + message), sans casser les
5 fonctions existantes (allproc, security_flags, qa_flags, utoken_flags,
root_vnode) qui restent inchangees.
